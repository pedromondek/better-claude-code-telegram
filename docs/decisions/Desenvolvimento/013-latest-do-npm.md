# 013. A latest do npm acompanha a pré-versão até a primeira estável, movida pelo release por OIDC

> **Versão:** 2 · **Decidido por:** pedromondek
> **Card:** [#24](https://github.com/pedromondek/better-claude-code-telegram/issues/24)
> **Branch:** `0024-move-the-npm-latest-tag-to-each-pre`
> **Criado em:** 2026-11-27 00:39 · **Atualizado em:** 2026-11-27 01:09
> **Âncoras:** `scripts/release-npm-publish.mjs` (`moveLatest`) · `scripts/release-publish.mjs` (`planLatest`) · `scripts/release-verify.mjs` (`latestProblems`) · `scripts/release.constants.mjs` (`MIN_DIST_TAG_NPM`) · `.github/workflows/release.yml` (`latest`, `only_latest`) · `.github/zizmor.yml`

**Decisão:** o job `latest` do `release.yml`, no environment `release`, com `id-token: write` e o npm 11.21.3 instalado no próprio job (a exceção `adhoc-packages` do zizmor vale só para essa linha), roda `npm run release:npm:publish -- latest` depois da aprovação do npm e antes do verify. O comando aponta a `latest` dos 7 pacotes para a pré-versão enquanto nenhuma versão estável está no npm, nunca leva a `latest` de volta de uma versão mais nova e não faz nada numa estável, que o npm já publica na `latest`. O `release:verify` confere a `latest` na versão ou numa mais nova enquanto não há estável. Um disparo manual com `only_latest` numa versão publicada (`ONLY_LATEST=true` no `release:publish -- plan`, que aceita só versão com Release publicado) roda só esse job e o verify, sem build, publicação nem anúncio. Cada pacote precisa da opção "Allow npm dist-tag" do trusted publisher, que só as configurações do pacote no npmjs.com ligam: o `npm trust github` não tem flag para ela.

**Porquê:** uma pré-versão publica só na dist-tag do estágio, então a `latest` ficava na versão para onde foi movida à mão, e o `npx` sem tag que o README ensina instalaria uma versão velha no lançamento público. O trusted publishing dos 7 pacotes só aceita o `release.yml` no environment `release`, e mover dist-tag por OIDC exige npm 11.21.0 ou mais novo, segundo a doc do npm (https://docs.npmjs.com/trusted-publishers, que também diz que a opção "Allow npm dist-tag" vem desligada e se liga nas configurações do pacote). O disparo só-latest testa o caminho real antes da beta, numa versão já publicada.

**Descartado:** mover a `latest` à mão a cada versão (trabalho repetido que se esquece); deixar a `latest` só para as estáveis (o `npx` sem tag instalaria a primeira alpha durante toda a fase de pré-versões); estrear o job na própria beta sem teste (se falhasse, a beta parava com os pacotes publicados e um novo disparo seria recusado no plano); mover à mão uma vez com o login do mantenedor (não testa o OIDC); instalar o npm por devDependency com lock (um pacote grande no projeto só para um job); exceção do zizmor para o `release.yml` inteiro (tiraria a auditoria de pacote avulso do arquivo todo).
